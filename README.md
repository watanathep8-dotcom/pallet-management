# Pallet Hub — ระบบบริหารพาเลท RM + PK + FG

เวอร์ชัน GitHub Pages + Google Apps Script (ย้ายมาจากเวอร์ชัน PHP/MySQL บน XAMPP)

- **หน้าเว็บ** (`docs/`) เป็นไฟล์ static เปิดบน GitHub Pages ได้เลย หน้าตาและการใช้งานเหมือนเดิมทุกอย่าง
- **ฐานข้อมูล** เป็น Google Sheet (1 ชีตต่อ 1 ตาราง: `pallet_types`, `departments`, `repairs`, `movements`, `audit_logs`, `users`)
- **ต้องเข้าสู่ระบบ** (ชื่อผู้ใช้ + รหัสผ่าน) ก่อนใช้งานทุกส่วน ผู้ดูแลระบบเป็นผู้สร้างบัญชี และทุกรายการ/Log บันทึกว่า **ใคร** เป็นผู้ทำ
- **API** เป็น Google Apps Script Web App (`apps-script/Code.gs`) กฎการทำงานเหมือน `api.php` เดิมทุกข้อ

## โครงสร้างไฟล์

```
docs/index.html          หน้าเว็บ (เดิมคือ index.php)
docs/config.js           ตั้งค่า apiUrl (URL ของ Apps Script /exec)
docs/assets/app.js       โค้ดหน้าเว็บ (เปลี่ยนเฉพาะส่วนเรียก API)
docs/assets/style.css    สไตล์ (เหมือนเดิม)
apps-script/Code.gs      โค้ดฝั่งเซิร์ฟเวอร์ (Google Apps Script)
appsscript.json          ไฟล์ manifest ของ Apps Script (เขตเวลา Asia/Bangkok, V8)
test/gas-mock.js         ชุดทดสอบ (Node.js) จำลอง Apps Script ในหน่วยความจำ — ไม่ได้เผยแพร่
```

## วิธีติดตั้ง (ทำครั้งเดียว)

### 1. สร้างโปรเจกต์ Apps Script
1. ไปที่ <https://script.google.com> → **New project** ตั้งชื่อ เช่น `Pallet Hub API`
2. ลบโค้ดเดิมในไฟล์ `Code.gs` แล้ว **คัดลอกเนื้อหาทั้งหมดจาก `apps-script/Code.gs`** ไปวาง
3. ไปที่ **Project Settings** (รูปเฟือง) → ติ๊ก **Show "appsscript.json" manifest file in editor**
4. กลับไปที่ Editor เปิดไฟล์ `appsscript.json` แล้ววางเนื้อหาจากไฟล์ `appsscript.json` ในโปรเจกต์นี้ (เขตเวลา `Asia/Bangkok`, runtime `V8`)
5. กด **Save**

### 2. สร้างฐานข้อมูล (Google Sheet)
1. เลือกฟังก์ชัน **`setupSystem`** ในแถบด้านบน แล้วกด **Run**
2. อนุญาตสิทธิ์ (Review permissions → เลือกบัญชี → Allow)
3. ระบบจะสร้างสเปรดชีต **"Pallet Hub Database"** ใน Google Drive พร้อมชีตทุกตาราง ประเภทพาเลท 4 แบบ และรายชื่อฝ่าย 8 ฝ่าย
   แล้วบันทึก ID ไว้ใน Script Properties (`PALLET_SPREADSHEET_ID`) — ดูลิงก์ได้ใน Execution log
4. รัน `setupSystem` ซ้ำได้ ระบบจะไม่สร้างสเปรดชีตใหม่ (ใช้ของเดิม และเติมชีต/ข้อมูลตั้งต้นที่ขาดเท่านั้น)

### 3. ตั้งรหัสผ่านผู้ดูแลระบบเริ่มต้น (Script Properties)
1. **Project Settings** → เลื่อนลงไปที่ **Script properties** → **Add script property**
2. Property: `PALLET_INITIAL_ADMIN_PASSWORD`  Value: รหัสผ่านเริ่มต้นของผู้ดูแลระบบ → **Save script properties**
3. (ไม่บังคับ) Property: `PALLET_RESET_PASSWORD` — รหัสรีเซ็ตข้อมูล ใช้กับปุ่ม "รีเซ็ตข้อมูล" และการแก้ไข/ลบรายการที่บันทึกแล้ว
4. รหัสผ่านเก็บใน Script Properties เท่านั้น **ไม่อยู่ในซอร์สโค้ด**

### 4. Deploy เป็น Web App
1. กด **Deploy → New deployment** → เลือกประเภท **Web app**
2. **Execute as:** `Me`  **Who has access:** `Anyone`
3. กด **Deploy** แล้วคัดลอก **Web app URL** (ลงท้ายด้วย `/exec`)
4. เมื่อแก้ `Code.gs` ภายหลัง ให้ **Deploy → Manage deployments → แก้ไข (ดินสอ) → Version: New version → Deploy** เพื่อให้ URL เดิมใช้โค้ดใหม่

### 5. ตั้งค่าหน้าเว็บ
1. เปิดไฟล์ `docs/config.js` แล้วใส่ URL:
   ```js
   window.PALLET_CONFIG = { apiUrl: "https://script.google.com/macros/s/xxxxxxxx/exec" };
   ```
2. อัปโหลดขึ้น GitHub แล้วเปิด GitHub Pages: **Settings → Pages → Branch: `main` / Folder: `/docs`**
3. ถ้ายังไม่ได้ใส่ `apiUrl` หน้าเว็บจะแสดงแถบแจ้งเตือน "ยังไม่ได้ตั้งค่า apiUrl"

### 6. เข้าสู่ระบบครั้งแรก และสร้างบัญชีผู้ใช้
1. เปิดหน้าเว็บ → เข้าสู่ระบบด้วยชื่อผู้ใช้ **`admin`** และรหัสผ่านที่ตั้งไว้ใน `PALLET_INITIAL_ADMIN_PASSWORD`
   (ใช้ได้เฉพาะตอนที่ชีต `users` ยังไม่มีบัญชีใดเลย ระบบจะสร้างบัญชี admin ชื่อ "ผู้ดูแลระบบ" ให้อัตโนมัติ)
2. ไปที่ **ตั้งค่าบัญชี** (รูปเฟือง) → **เปลี่ยนรหัสผ่าน** ของ admin ทันที
3. หลังเข้าสู่ระบบครั้งแรกแล้ว **ลบ Script Property `PALLET_INITIAL_ADMIN_PASSWORD` ได้เลย** (ระบบไม่ใช้ค่านี้อีกเมื่อมีบัญชีแล้ว)
4. ที่หน้า **ตั้งค่าบัญชี** ผู้ดูแลระบบสร้างบัญชีให้พนักงาน (ชื่อผู้ใช้ ชื่อ-นามสกุล สิทธิ์ รหัสผ่านเริ่มต้น)

### อัปเดตจากเวอร์ชันก่อน (มีข้อมูลอยู่แล้ว)
- วาง `Code.gs` ใหม่ → **Deploy → Manage deployments → New version** (URL เดิม) แล้วตั้ง `PALLET_INITIAL_ADMIN_PASSWORD` ตามข้อ 3
- ไม่ต้องสร้างสเปรดชีตใหม่ ข้อมูลเดิมอยู่ครบ: ชีต `users` จะถูกสร้างให้อัตโนมัติเมื่อเข้าสู่ระบบครั้งแรก และคอลัมน์ใหม่
  (`movements`: `actor`, `username` · `repairs`: `reported_username`, `updated_by`, `updated_username`, `updated_at` · `audit_logs`: `username`)
  จะถูกเพิ่มต่อท้ายหัวตารางเองเมื่อมีการใช้งาน (หรือรัน `setupSystem` ซ้ำเพื่ออัปเกรดทันที) — รายการเดิมจะแสดงผู้ทำรายการเป็น "ข้อมูลเดิม"
- `PALLET_ACTION_PASSWORD` (รหัสบันทึกข้อมูลแบบเดิม) **ไม่ใช้แล้ว** ลบออกจาก Script Properties ได้

## การใช้งาน

- **เข้าสู่ระบบ** ก่อนใช้งานทุกหน้า (ทั้งดูข้อมูลและบันทึก) — เซสชันอยู่ได้ 6 ชั่วโมง (เก็บ token ในเบราว์เซอร์ ไม่เก็บรหัสผ่าน)
  เมื่อหมดอายุ/ถูกปิดบัญชี/รหัสผ่านถูกเปลี่ยน ระบบจะกลับไปหน้าเข้าสู่ระบบเอง
- ใส่รหัสผ่านผิดเกิน 10 ครั้งภายใน 15 นาที ชื่อผู้ใช้นั้นจะถูกระงับการเข้าสู่ระบบชั่วคราว 15 นาที (ผู้ดูแลระบบตั้งรหัสใหม่ให้เพื่อปลดได้)
- **มุมขวาบน** แสดงชื่อผู้ที่เข้าสู่ระบบ กดเพื่อเปิดเมนู **ตั้งค่าบัญชี** (เปลี่ยนรหัสผ่านของตนเอง) และ **ออกจากระบบ**
- **ตั้งค่าบัญชี** (ผู้ดูแลระบบ): ดูรายชื่อบัญชี (ชื่อผู้ใช้ ชื่อ สิทธิ์ สถานะ เข้าสู่ระบบล่าสุด), สร้างบัญชี, ตั้งรหัสผ่านใหม่ให้ผู้ใช้,
  เปิด/ปิดใช้งาน, เปลี่ยนสิทธิ์ (ผู้ดูแลระบบ / ผู้ใช้งาน) — ต้องมีผู้ดูแลระบบที่ใช้งานอยู่อย่างน้อย 1 คนเสมอ;
  ปิดใช้งานบัญชี / ตั้งรหัสใหม่ / เปลี่ยนรหัสผ่าน = ผู้ใช้นั้นถูกออกจากระบบทุกเครื่อง
- **ผู้ทำรายการ**: เซิร์ฟเวอร์บันทึกจากบัญชีที่เข้าสู่ระบบเสมอ ในรูป `ชื่อ (username)` ในทุกรายการเคลื่อนไหว ใบแจ้งซ่อม และ Log
  (คอลัมน์ "ผู้ทำรายการ / By" ในหน้า ประวัติเคลื่อนไหว และ Log) ช่องชื่อในฟอร์มเป็นเพียงชื่อที่ระบุเพิ่มเติม (ไม่บังคับ)
- การเข้าสู่ระบบ/ออกจากระบบ การเข้าสู่ระบบไม่สำเร็จ และการจัดการบัญชีทุกอย่าง บันทึกใน Log หมวด "บัญชีผู้ใช้"
- **แก้ไข / ลบรายการที่บันทึกแล้ว** (ปุ่ม ✏️ แก้ไข / 🗑 ลบ ในหน้า ประวัติเคลื่อนไหว และ งานซ่อม) ต้องเข้าสู่ระบบ **และ** ใส่ **รหัสรีเซ็ตข้อมูล**
  (Script Property `PALLET_RESET_PASSWORD` — ตัวนับการใส่ผิด/ล็อกร่วมกับการรีเซ็ตข้อมูล)
  - แก้ไขรายการได้เฉพาะ จำนวน วันที่/เวลา ฝ่าย (รายการเบิก/คืน/คืนชำรุด) ผู้ทำรายการ หมายเหตุ — เปลี่ยนรายการ/ประเภท/ขนาด/สถานะ ให้ลบแล้วบันทึกใหม่
  - ใบแจ้งซ่อมแก้ได้เฉพาะ สาเหตุ ช่างผู้ซ่อม หมายเหตุ (ผู้แจ้งบันทึกจากบัญชีผู้ใช้ แก้ไม่ได้)
  - งานซ่อม (แจ้งชำรุด → ส่งซ่อม → ซ่อมเสร็จ/ตัดจำหน่าย + ใบแจ้งซ่อม) ถือเป็นชุดเดียว: ลบรายการใดในชุด = ลบทั้งชุด,
    แก้จำนวนรายการใดในชุด = ปรับจำนวนทุกรายการและใบแจ้งซ่อม, วันที่ในชุดต้องเรียงตามลำดับ (และอัปเดตวันที่ในใบแจ้งซ่อม)
  - ก่อนบันทึก เซิร์ฟเวอร์จะคำนวณย้อนทุกรายการตามลำดับเวลา ถ้ายอดคงเหลือ (ประเภท×ขนาด×สถานะ) หรือยอดที่ฝ่ายถืออยู่จะติดลบ ณ เวลาใด
    จะปฏิเสธพร้อมเหตุผล เช่น `ลบไม่ได้: ยอดพร้อมใช้ RM 1.2x1.2 จะติดลบ (-5) ณ วันที่ ...` และไม่เปลี่ยนแปลงข้อมูลใด ๆ
  - ทุกการแก้ไข/ลบบันทึกใน Log (ก่อน → หลัง และชื่อผู้ทำ); เลขที่เอกสารที่ถูกลบจะไม่ถูกนำกลับมาใช้ซ้ำ
- **ส่งออก Excel**: ปุ่ม Excel ในหน้า ประวัติเคลื่อนไหว และ บันทึกประวัติ (Log) จะดาวน์โหลดไฟล์ CSV (UTF-8 BOM เปิดใน Excel ได้ภาษาไทยถูกต้อง)
- ช่อง IP ใน Log จะแสดงเป็น `web` เพราะ Apps Script ไม่สามารถเห็น IP ของผู้ใช้

## สถานะพาเลท

```
ภายนอก --รับเข้า--> พร้อมใช้ --เบิกจ่าย(ฝ่าย)--> เบิกไปใช้งาน --รับคืน--> พร้อมใช้
พร้อมใช้ / รับคืนสภาพชำรุด --> ชำรุด --ส่งซ่อม--> กำลังซ่อม --ซ่อมเสร็จ--> พร้อมใช้
ชำรุด / กำลังซ่อม --ซ่อมไม่ได้--> ตัดจำหน่าย
```

## API (สำหรับนักพัฒนา)

- เข้าสู่ระบบ: `POST { action: "login", username, password }` → `{ token, expires_in, user: { id, username, fullname, role, ... } }`
- ทุกคำสั่งอื่นต้องส่ง `token` (GET: `&token=...`, POST: ฟิลด์ `token`) ถ้าไม่มี/หมดอายุ → `{ ok: false, code: "AUTH", error: "กรุณาเข้าสู่ระบบ" }`
- อ่านข้อมูล: `GET <apiUrl>?action=<action>&token=...&...` → `{ ok: true, data }` หรือ `{ ok: false, error, code? }`
  - `bootstrap`, `dashboard` (`days`=7/14/30), `repairs`, `history` / `export` (`from`, `to`, `type`, `act`, `dept`, `q`), `logs` / `logs_export` (`from`, `to`, `cat`, `q`), `me`, `users` (ผู้ดูแลระบบ)
- บันทึกข้อมูล: `POST <apiUrl>` header `Content-Type: text/plain;charset=UTF-8` body JSON `{ action, token, ... }`
  - `receive`, `issue`, `return`, `damage`, `repair_start`, `repair_done`, `scrap`, `dept_save`, `dept_delete`
  - บัญชี: `logout`, `change_password` (`old_password`, `new_password`) และสำหรับผู้ดูแลระบบ: `user_save` (สร้าง: `username`, `fullname`, `role`, `password` /
    แก้ไข: `id`, `fullname`, `role`, `active`), `user_reset_password` (`id`, `password`), `user_toggle` (`id`)
  - ต้องมี `resetPassword` เพิ่ม: `reset_data`, `verifyResetPassword`, `movement_update` (`id`, `doc_no`, `qty`, `date`, `time`, `department`, `person`, `note`),
    `movement_delete` (`id`, `doc_no`), `repair_update` (`id`, `ticket_no`, `cause`, `repairer`, `note`), `repair_delete` (`id`, `ticket_no`)
  - ผู้ทำรายการ (`actor` / `username` / `reported_by` / `updated_by`) เซิร์ฟเวอร์กำหนดจาก session เสมอ — ค่าที่หน้าเว็บส่งมาจะถูกละเลย
- ทุกการบันทึกทำภายใต้ `LockService` (ป้องกันเลขที่เอกสารซ้ำเมื่อบันทึกพร้อมกัน)

## หมายเหตุ

- ฟอนต์ ไอคอน และกราฟโหลดจาก CDN (Google Fonts, cdnjs) ต้องต่ออินเทอร์เน็ต

- ห้ามแก้ไขหัวตาราง (แถวที่ 1) ในชีต — แก้ข้อมูลในแถวอื่นได้ แต่ควรทำผ่านหน้าเว็บเพื่อให้มี Log
