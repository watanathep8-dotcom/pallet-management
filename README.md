# Pallet Hub — ระบบบริหารพาเลท RM + PK + FG

เวอร์ชัน GitHub Pages + Google Apps Script (ย้ายมาจากเวอร์ชัน PHP/MySQL บน XAMPP)

- **หน้าเว็บ** (`docs/`) เป็นไฟล์ static เปิดบน GitHub Pages ได้เลย หน้าตาและการใช้งานเหมือนเดิมทุกอย่าง
- **ฐานข้อมูล** เป็น Google Sheet (1 ชีตต่อ 1 ตาราง: `pallet_types`, `departments`, `repairs`, `movements`, `audit_logs`)
- **ไม่ต้องเข้าสู่ระบบ** เปิดหน้าเว็บแล้วใช้งานได้ทันที ชื่อที่ตั้งไว้มุมขวาบนจะถูกบันทึกเป็น "ผู้ทำรายการ" ในทุกรายการ/Log
- แก้ไข/ลบรายการ, รีเซ็ตข้อมูล และดูบันทึกประวัติ (Log) ต้องใช้ **รหัสรีเซ็ตข้อมูล** (`PALLET_RESET_PASSWORD`)
- **API** เป็น Google Apps Script Web App (`apps-script/Code.gs`) กฎการทำงานเหมือน `api.php` เดิมทุกข้อ

## โครงสร้างไฟล์

```
docs/index.html          หน้าเว็บ (เดิมคือ index.php)
docs/config.js           ตั้งค่า apiUrl (URL ของ Apps Script /exec)
docs/assets/app.js       โค้ดหน้าเว็บ (เปลี่ยนเฉพาะส่วนเรียก API)
docs/assets/style.css    สไตล์ (เหมือนเดิม)
apps-script/Code.gs      โค้ดฝั่งเซิร์ฟเวอร์ (Google Apps Script)
appsscript.json          ไฟล์ manifest ของ Apps Script (เขตเวลา Asia/Bangkok, V8)
test/gas-mock.js         ชุดทดสอบ (Node.js) จำลอง Apps Script ในหน่วยความจำ — ไม่ได้เผยแพร่
```

## วิธีติดตั้ง (ทำครั้งเดียว)

### 1. สร้างโปรเจกต์ Apps Script
1. ไปที่ <https://script.google.com> → **New project** ตั้งชื่อ เช่น `Pallet Hub API`
2. ลบโค้ดเดิมในไฟล์ `Code.gs` แล้ว **คัดลอกเนื้อหาทั้งหมดจาก `apps-script/Code.gs`** ไปวาง
3. ไปที่ **Project Settings** (รูปเฟือง) → ติ๊ก **Show "appsscript.json" manifest file in editor**
4. กลับไปที่ Editor เปิดไฟล์ `appsscript.json` แล้ววางเนื้อหาจากไฟล์ `appsscript.json` ในโปรเจกต์นี้ (เขตเวลา `Asia/Bangkok`, runtime `V8`)
5. กด **Save**

### 2. สร้างฐานข้อมูล (Google Sheet)
1. เลือกฟังก์ชัน **`setupSystem`** ในแถบด้านบน แล้วกด **Run**
2. อนุญาตสิทธิ์ (Review permissions → เลือกบัญชี → Allow)
3. ระบบจะสร้างสเปรดชีต **"Pallet Hub Database"** ใน Google Drive พร้อมชีตทุกตาราง ประเภทพาเลท 4 แบบ และรายชื่อฝ่าย 8 ฝ่าย
   แล้วบันทึก ID ไว้ใน Script Properties (`PALLET_SPREADSHEET_ID`) — ดูลิงก์ได้ใน Execution log
4. รัน `setupSystem` ซ้ำได้ ระบบจะไม่สร้างสเปรดชีตใหม่ (ใช้ของเดิม และเติมชีต/ข้อมูลตั้งต้นที่ขาดเท่านั้น)

### 3. ตั้งรหัสรีเซ็ตข้อมูล (Script Properties)
1. **Project Settings** → เลื่อนลงไปที่ **Script properties** → **Add script property**
2. Property: `PALLET_RESET_PASSWORD`  Value: รหัสรีเซ็ตข้อมูล → **Save script properties**
   ใช้กับปุ่ม "รีเซ็ตข้อมูล", การแก้ไข/ลบรายการที่บันทึกแล้ว และการดูบันทึกประวัติ (Log)
3. รหัสเก็บใน Script Properties เท่านั้น **ไม่อยู่ในซอร์สโค้ด**

### 4. Deploy เป็น Web App
1. กด **Deploy → New deployment** → เลือกประเภท **Web app**
2. **Execute as:** `Me`  **Who has access:** `Anyone`
3. กด **Deploy** แล้วคัดลอก **Web app URL** (ลงท้ายด้วย `/exec`)
4. เมื่อแก้ `Code.gs` ภายหลัง ให้ **Deploy → Manage deployments → แก้ไข (ดินสอ) → Version: New version → Deploy** เพื่อให้ URL เดิมใช้โค้ดใหม่

### 5. ตั้งค่าหน้าเว็บ
1. เปิดไฟล์ `docs/config.js` แล้วใส่ URL:
   ```js
   window.PALLET_CONFIG = { apiUrl: "https://script.google.com/macros/s/xxxxxxxx/exec" };
   ```
2. อัปโหลดขึ้น GitHub แล้วเปิด GitHub Pages: **Settings → Pages → Branch: `main` / Folder: `/docs`**
3. ถ้ายังไม่ได้ใส่ `apiUrl` หน้าเว็บจะแสดงแถบแจ้งเตือน "ยังไม่ได้ตั้งค่า apiUrl"

### 6. (แนะนำ) ตั้ง keep-warm ให้แคชพร้อมเสมอ — ทำครั้งเดียว
1. ใน Apps Script editor เลือกฟังก์ชัน **`installKeepWarmTrigger`** แล้วกด **Run** (ครั้งแรกจะขออนุญาตสิทธิ์เพิ่ม "จัดการ trigger" → Allow)
2. ระบบจะสร้าง trigger แบบตั้งเวลา **ทุก 10 นาที** ให้รันฟังก์ชัน `keepWarm` (รันซ้ำได้ — จะลบ trigger keepWarm เดิมก่อนเสมอ จึงมีแค่ 1 ตัว)
   ดูได้ที่เมนู **Triggers** (รูปนาฬิกา) ด้านซ้าย · ยกเลิกได้ด้วยการรัน `removeKeepWarmTrigger`
3. `keepWarm` อ่านข้อมูลที่หน้าเว็บใช้เปิดหน้า (bootstrap / แดชบอร์ด / งานซ่อม) จากชีตแล้วเก็บไว้ในแคช (CacheService)
   คำขอถัดไปจากหน้าเว็บจึงตอบจากแคชได้ทันทีโดยไม่ต้องอ่านชีต — **อ่านอย่างเดียว** ไม่เขียนข้อมูลลงชีต และไม่เปลี่ยนเวอร์ชันข้อมูล
4. หมายเหตุ: ประโยชน์หลักคือ **ทำให้แคชข้อมูลพร้อมอยู่เสมอ** ส่วนอาการ "เปิดครั้งแรกช้า" ของ Google เอง (cold start ของ Web App)
   อาจดีขึ้นหรือไม่ก็ได้ เพราะ trigger กับคำขอจากหน้าเว็บไม่จำเป็นต้องใช้เครื่อง/อินสแตนซ์เดียวกัน (Google ไม่รับประกัน)
5. trigger ใช้โควตาเวลารันของบัญชี Google เล็กน้อย (วันละ 144 ครั้ง ครั้งละไม่กี่วินาที)

### 7. (ไม่บังคับ) แจ้งเตือนใน Microsoft Teams
1. ใน Teams เปิดช่อง (channel) ที่ต้องการ → **⋯ → Workflows** → เลือกเทมเพลต
   **"Post to a channel when a webhook request is received"** → เลือก Team/Channel → **Add workflow** แล้วคัดลอก URL ที่ได้
2. Apps Script → **Project Settings → Script properties** → เพิ่ม `TEAMS_WEBHOOK_URL` = URL นั้น
   (เก็บใน Script Properties เท่านั้น **ห้ามใส่ในซอร์สโค้ด** — ไม่ตั้ง/ค่าว่าง = ไม่แจ้งเตือน ระบบทำงานปกติ)
3. เลือกฟังก์ชัน **`testTeamsNotification`** แล้วกด **Run** — ครั้งแรกจะขออนุญาตสิทธิ์ใหม่
   "เชื่อมต่อกับบริการภายนอก" (`script.external_request`) → Allow · ผลใน Execution log ต้องได้ `"sent":true` (HTTP 2xx) และเห็นการ์ดทดสอบในช่อง
4. **Deploy → Manage deployments → New version** เพื่อให้ Web App ใช้โค้ดใหม่
5. สิ่งที่แจ้ง (การ์ดสีแดง 1 ใบต่อเหตุการณ์ พร้อมชื่อผู้ทำรายการ เวลาไทย และปุ่ม "เปิด Pallet Hub"):
   แจ้งชำรุด/รับคืนชำรุด (เลขใบแจ้งซ่อม ประเภท ขนาด จำนวน ที่มา สาเหตุ), ซ่อมเสร็จ, ซ่อมไม่ได้/ตัดจำหน่าย,
   แก้ไข/ลบรายการ/ใบแจ้งซ่อม และรีเซ็ตข้อมูล (รายละเอียด ก่อน → หลัง เหมือนใน Log) — รับเข้า/เบิก/รับคืนปกติ **ไม่แจ้ง**
6. ส่งหลังบันทึกสำเร็จและปลดล็อกแล้ว ถ้า Teams ล่มหรือ URL ผิด การบันทึกยังสำเร็จตามปกติ (ดูสาเหตุใน Executions: HTTP status)
   ลิงก์ในการ์ดใช้ `PALLET_SITE_URL` (Script Property) ถ้าตั้งไว้ ไม่งั้นใช้ https://watanathep8-dotcom.github.io/pallet-management/

### อัปเดตจากเวอร์ชันก่อน (มีข้อมูลอยู่แล้ว)
- วาง `Code.gs` ใหม่ → **Deploy → Manage deployments → New version** (URL เดิม) แล้วอัปโหลด `docs/` ใหม่
- ไม่ต้องสร้างสเปรดชีตใหม่ ข้อมูลเดิมอยู่ครบ: สเปรดชีตจากเวอร์ชันที่มีระบบเข้าสู่ระบบใช้ได้ทันที — คอลัมน์ `username`
  (`movements`, `audit_logs`) และ `reported_username` / `updated_username` (`repairs`) ยังอยู่ (รายการใหม่เว้นว่าง) และชีต `users` ไม่ถูกใช้และไม่ถูกแก้ไข
  รายการที่บันทึกช่วงที่มีระบบเข้าสู่ระบบยังแสดงชื่อผู้ทำรายการเดิม
- สเปรดชีตที่เก่ากว่านั้น: คอลัมน์ใหม่จะถูกเพิ่มต่อท้ายหัวตารางเองเมื่อมีการใช้งาน (หรือรัน `setupSystem` ซ้ำ)
- `PALLET_INITIAL_ADMIN_PASSWORD` และ `PALLET_ACTION_PASSWORD` **ไม่ใช้แล้ว** ลบออกจาก Script Properties ได้

## การใช้งาน

- **ผู้ใช้งาน** (มุมขวาบน): กดเพื่อตั้งชื่อของคุณ (เก็บในเบราว์เซอร์นี้) — ชื่อนี้ถูกบันทึกเป็น **ผู้ทำรายการ** ในทุกรายการเคลื่อนไหว
  ใบแจ้งซ่อม และ Log (คอลัมน์ "ผู้ทำรายการ / By") ช่องชื่อในฟอร์มเป็นเพียงชื่อที่ระบุเพิ่มเติม (ไม่บังคับ)
- **บันทึกประวัติ (Log)** ต้องใส่ **รหัสรีเซ็ตข้อมูล** ก่อนแสดง (ถามครั้งเดียวต่อการเปิดหน้าเว็บ ใช้ร่วมกับการแก้ไข/ลบรายการ)
- **แก้ไข / ลบรายการที่บันทึกแล้ว** (ปุ่ม ✏️ แก้ไข / 🗑 ลบ ในหน้า ประวัติเคลื่อนไหว และ งานซ่อม) ต้องใส่ **รหัสรีเซ็ตข้อมูล**
  (Script Property `PALLET_RESET_PASSWORD` — ตัวนับการใส่ผิด/ล็อกร่วมกับการรีเซ็ตข้อมูลและการดู Log: ผิดเกิน 10 ครั้งใน 15 นาที = ล็อก 15 นาที)
  - แก้ไขรายการได้เฉพาะ จำนวน วันที่/เวลา ฝ่าย (รายการเบิก/คืน/คืนชำรุด) ผู้ทำรายการ หมายเหตุ — เปลี่ยนรายการ/ประเภท/ขนาด/สถานะ ให้ลบแล้วบันทึกใหม่
  - ใบแจ้งซ่อมแก้ได้เฉพาะ สาเหตุ ช่างผู้ซ่อม หมายเหตุ (ผู้แจ้งบันทึกจากชื่อผู้ใช้งาน แก้ไม่ได้)
  - งานซ่อม (แจ้งชำรุด → ส่งซ่อม → ซ่อมเสร็จ/ตัดจำหน่าย + ใบแจ้งซ่อม) ถือเป็นชุดเดียว: ลบรายการใดในชุด = ลบทั้งชุด,
    แก้จำนวนรายการใดในชุด = ปรับจำนวนทุกรายการและใบแจ้งซ่อม, วันที่ในชุดต้องเรียงตามลำดับ (และอัปเดตวันที่ในใบแจ้งซ่อม)
    — ตอนกด ส่งซ่อม / ซ่อมเสร็จ / ซ่อมไม่ได้ ก็ใส่วันที่ก่อนขั้นตอนก่อนหน้าของใบเดียวกันไม่ได้เช่นกัน
  - ก่อนบันทึก เซิร์ฟเวอร์จะคำนวณย้อนทุกรายการตามลำดับเวลา ถ้ายอดคงเหลือ (ประเภท×ขนาด×สถานะ) หรือยอดที่ฝ่ายถืออยู่จะติดลบ ณ เวลาใด
    จะปฏิเสธพร้อมเหตุผล เช่น `ลบไม่ได้: ยอดพร้อมใช้ RM 1.2x1.2 จะติดลบ (-5) ณ วันที่ ...` และไม่เปลี่ยนแปลงข้อมูลใด ๆ
  - ทุกการแก้ไข/ลบบันทึกใน Log (ก่อน → หลัง และชื่อผู้ทำ); เลขที่เอกสารที่ถูกลบจะไม่ถูกนำกลับมาใช้ซ้ำ
- **ส่งออก Excel**: ปุ่ม Excel ในหน้า ประวัติเคลื่อนไหว และ บันทึกประวัติ (Log) จะดาวน์โหลดไฟล์ CSV (UTF-8 BOM เปิดใน Excel ได้ภาษาไทยถูกต้อง)
- ช่อง IP ใน Log จะแสดงเป็น `web` เพราะ Apps Script ไม่สามารถเห็น IP ของผู้ใช้

## API (สำหรับนักพัฒนา)

- อ่านข้อมูล: `GET <apiUrl>?action=<action>&...` → `{ ok: true, data }` หรือ `{ ok: false, error, code? }`
  - `bootstrap`, `dashboard` (`days`=7/14/30), `repairs`, `history` / `export` (`from`, `to`, `type`, `act`, `dept`, `q`)
  - `batch` (`reads` = JSON `[{action, ...params}, ...]` สูงสุด 6 รายการจาก bootstrap/dashboard/repairs/history) → `{ results: [...] }`
    ผลเหมือนเรียกทีละคำสั่ง แต่ใช้คำขอเดียว
  - `logs` / `logs_export` (`from`, `to`, `cat`, `q`) ต้องส่งแบบ **POST** พร้อม `resetPassword`
- บันทึกข้อมูล: `POST <apiUrl>` header `Content-Type: text/plain;charset=UTF-8` body JSON `{ action, actor, ... }`
  - `receive`, `issue`, `return`, `damage`, `repair_start`, `repair_done`, `scrap`, `dept_save`, `dept_delete` (ไม่ต้องใช้รหัส)
  - ต้องมี `resetPassword` เพิ่ม: `reset_data`, `verifyResetPassword`, `movement_update` (`id`, `doc_no`, `qty`, `date`, `time`, `department`, `person`, `note`),
    `movement_delete` (`id`, `doc_no`), `repair_update` (`id`, `ticket_no`, `cause`, `repairer`, `note`), `repair_delete` (`id`, `ticket_no`)
  - `actor` = ชื่อผู้ใช้งานจากหน้าเว็บ บันทึกเป็นผู้ทำรายการ (`actor` / `reported_by` / `updated_by`); `username` เว้นว่าง
  - ใส่ `reads` (รูปแบบเดียวกับ `batch`) ได้ทุกคำสั่งบันทึก → ผลมี `reads: [...]` = ข้อมูลหลังบันทึก (หน้าเว็บไม่ต้องโหลดซ้ำ)
- แคชการอ่าน (CacheService): แถวข้อมูลของแต่ละชีตและ bootstrap ถูกแคชตาม "เวอร์ชันข้อมูล" ของชีต ทุกการบันทึกผ่าน API
  เปลี่ยนเวอร์ชันทันทีหลังเขียนชีตเสร็จ จึงไม่ได้ข้อมูลเก่าหลังบันทึก — ถ้าแก้ข้อมูลในชีตด้วยมือ จะเห็นผลภายใน 10 นาที
  (ถ้าเปิด keep-warm ไว้: ภายในรอบถัดไปของ `keepWarm` ไม่เกินประมาณ 10–15 นาที)
  หรือรันฟังก์ชัน `clearReadCache()` ใน Apps Script editor เพื่อให้เห็นทันที
- `keepWarm()` / `installKeepWarmTrigger()` / `removeKeepWarmTrigger()` / `testTeamsNotification()` รันจาก editor หรือ trigger เท่านั้น (เรียกผ่าน URL ของ Web App ไม่ได้)
- ทุกการบันทึกทำภายใต้ `LockService` (ป้องกันเลขที่เอกสารซ้ำเมื่อบันทึกพร้อมกัน)

## หมายเหตุ

- ฟอนต์ ไอคอน และกราฟโหลดจาก CDN (Google Fonts, cdnjs) ต้องต่ออินเทอร์เน็ต
- Google Sheets ช้ากว่า MySQL แต่ละคำสั่งอาจใช้เวลา 1–3 วินาที — หน้าเว็บจึงรวมการอ่านของแต่ละหน้าเป็นคำขอเดียว (batch),
  แสดงข้อมูลล่าสุดที่จำไว้ในเบราว์เซอร์ทันทีแล้วโหลดใหม่เบื้องหลัง และรับข้อมูลหลังบันทึกมาพร้อมผลการบันทึก
- ห้ามแก้ไขหัวตาราง (แถวที่ 1) ในชีต — แก้ข้อมูลในแถวอื่นได้ แต่ควรทำผ่านหน้าเว็บเพื่อให้มี Log
